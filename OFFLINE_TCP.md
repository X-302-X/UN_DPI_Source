# Офлайн-разбор TCP-пакетов

`core/dpi/src/traffic/packet.rs` структурно разбирает IPv4/IPv6 и TCP/UDP, ограничивая чтение объявленной длиной IP-пакета. Для TCP дополнительно выдаются sequence, acknowledgment, флаги, window, checksum, urgent pointer, сырые options и payload. Для UDP поле TCP отсутствует. Сам `parse_ip` не проверяет контрольные суммы или семантику options.

`core/dpi/src/traffic/offline_tcp.rs` — адаптер для **исключительно синтетических и заранее размеченных** пакетов. Он отдельно проверяет поддерживаемые TCP options и checksum (см. [TCP_OPTIONS_CHECKSUM.md](TCP_OPTIONS_CHECKSUM.md)), принимает объект `Connections`, сырые IP-байты и явный тип события (открытие, SYN+ACK, клиентский ACK, данные или закрытие), затем проверяет ожидаемое направление и нормализованную пару адресов/портов. Из исходящего SYN без данных создаётся непрозрачный handle с token из таблицы; остальные операции должны использовать его. Адаптер не является автоматическим диспетчером пакетов и не сохраняет свою карту потоков.

## Ограничения адаптера

- Поддерживаются IPv4 без IP options и IPv6 без extension headers, TCP с ограниченным набором options и нулевыми reserved/NS и urgent pointer. Фрагменты IP, неподдерживаемые заголовки и варианты отбрасываются. ECN-флаги, TCP Fast Open, SYN с данными и финальный ACK с данными не поддерживаются.
- Контрольные суммы проверяются в предположении готового полного пакета без checksum и segmentation offload. Для реального Windows-перехвата это предположение может быть неверно. Проверка суммы не подтверждает подлинность пакета и соответствие состояния TCP.
- Формы TCP-флагов для каждого явного типа события проверяются по строгому списку. События, которые не соответствуют ожидаемой форме для совпавшего потока, отправляют его в карантин. Повреждённый или неподдерживаемый пакет, переданный в адаптер, отключает всю таблицу: нельзя достоверно установить, какие байты были пропущены. Пользователь адаптера сам обязан определять, какие пакеты следует в него передавать, и инвалидировать состояние при потере событий.
- `FlowMismatch` означает несовпадение рассчитанной пары адресов/портов с handle; событие не изменяет этот поток. Его корректная маршрутизация или признание потери события остаются задачей вызывающего кода. Переданное направление, подлинность пакета и соответствие пакета экземпляру TCP-соединения этим модулем не подтверждаются.
- Нет проверки TCP-окон, согласования options между сторонами, соответствия ACK в сегментах данных и последовательности FIN/RST, подтверждения фактической доставки, PID, межсетевых гонок или сетевых эффектов. FIN/RST прекращает только офлайн-наблюдение. Token и карантин не доказывают, что задержанный пакет относится к конкретному соединению.
- Адаптер нельзя подключать к реальному сетевому перехвату или использовать как единственное основание для изменения трафика. Необходимы отдельные проектирование, проверки и Windows-тесты. `evidence()` — предварительный результат, а не разрешение на вмешательство; при ECH внутренний домен не известен.

## Тесты

`core/dpi/tests/offline_tcp.rs` использует построенные в памяти IPv4/IPv6 и TCP-пакеты. Проверяются поля, размер заголовка, границы, обрезанные и неподдерживаемые пакеты, флаги, tuple/direction, ошибки и конфликты, проверка handshake, TCP options и checksum, повторное использование tuple, разбитые HTTP и TLS ClientHello, ECH. Фикстуры не проходят через драйвер или настоящую сеть.
